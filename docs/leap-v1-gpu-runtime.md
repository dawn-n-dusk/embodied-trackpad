# LEAP v1 GPU runtime (user-owned SuperPOD) — one-H800 smoke

2026-10-31. Second item of the first batch in
`docs/tasks/v1-training-and-monitoring-20261031.zh-CN.md`: an independent,
user-owned GPU Python runtime plus ONE bounded one-H800 smoke job for the
LEAP v1 Full 16-channel hand. This is a **runtime smoke**, not policy
training, not a pi0.5 run, and not an 8192-world claim (8192 stays
deferred).

## Measured result (independently reviewed)

The one-H800 allocation completed in **150 seconds**, exit `0:0`, and released
its resources. The executed hand-only smoke recorded **28 passing checks**
(including explicitly disclosure-only penetration entries), and the coordinator
ran **23 focused tests**. PyTorch `2.8.0+cu128` performed a BF16 forward/backward
pass and one diagnostic optimizer update on the actual NVIDIA H800 with driver
`580.173.02`. This was not project policy training.

| Worlds | Steps per world | Whole measured loop | Aggregate world-steps/s |
| --- | --- | --- | --- |
| 1 | 3300 | 19.591 s | 168.4 |
| 32 | 3300 | 19.784 s | 5337.5 |

Initial isolated compilation/warmup took about 93 seconds and is separate from
the table. The CPU reference measured about 19,898 steps/s for one world. This
small, synchronous diagnostic does not establish a GPU speedup or training
throughput. No 8192-world test was attempted. The scheduler allocated 28 CPUs
by default; numerical libraries used one thread.

[The acceptance record](../experiments/records/leap-v1-h800-runtime-20261031.json)
retains sampling limits, source hashes, unknown GPU warning counters, and
resource-accounting limitations. Environment + cache used 10.73 GiB; cumulative
network download bytes were not measured. Post-run verification matched all
48 source/asset files; 14 generated bytecode cache files had changed. Future
deployment bundles must exclude `__pycache__` and other generated files.

## Smoke contract (`tools/leap_v1_gpu_smoke.py`)

Canonical sources are sha256-pinned at runtime (`leap_v1/model.py`,
`leap_v1/diagnostics.py`); a mismatch aborts before any run. The v1 asset
manifest verifies itself on load.

1. **Frozen short schedule.** Derived from the accepted
   `diagnostics.build_script`: two-channel sweep subset (`if_mcp`,
   `if_pip`; contact-free movement) plus the spread and flex/return phases
   (may produce self-contact). Filtered-out sweep gaps are removed with
   durations and motion content unchanged (6.6 s / 3300 steps at the 2 ms
   timestep). Rows are validated (shape/finite/ctrlrange) and sha256
   reported; CPU and every GPU world consume the same row at the same step.
2. **Canonical reset.** `mj_resetData` + all-zero open pose + zero ctrl +
   `mj_forward` is the only live qpos write. GPU worlds are the broadcast of
   the same host reset; the pre-step audit requires exact equality in the
   actual backend dtype (float32 on mujoco-warp 3.17) across ALL worlds —
   the f64 hash is provenance only.
3. **CPU reference.** Every-step coverage: finite state, joint-limit
   excursion, tracking error, self-contact counts/penetration per phase,
   solver warnings; step/observation timing split.
4. **GPU stages 1 → 32.** mujoco-warp on the allocated device; world0
   contacts/joints sampled every 20 steps + final, all-world state every
   100 steps + final; capacity verdict uses naconmax (aggregate hard cap)
   and njmax (per-world hard cap); GPU solver-warning counters stay UNKNOWN
   (not transferred by `get_data_into`); CPU/GPU world0 final difference is
   reported honestly against the declared tolerances (limit excursion
   ≤ 0.01 rad, final open error ≤ 0.05 rad, CPU/GPU final qpos ≤ 0.01 rad).
   Self-contact penetration is disclosed with a 1 mm reference but NOT
   gated — the accepted v1 diagnostics report physical measurements rather
   than gating them, and the flex/spread phases are expected to produce
   self-contact (CPU reference measured 1.03 mm peak at contact onset).
5. **torch BF16 runtime smoke.** Requires the actual allocated device to be
   an NVIDIA H800; one BF16 forward/backward and ONE AdamW update on a
   small diagnostic linear model (label: runtime smoke, NOT project policy
   training).

`--tiny` / `--cpu-only` / `--skip-torch` are harness-mechanics modes only and
are never GPU or runtime-acceptance results.

## Operating procedure (operator-side summary)

All site identity comes from the environment or the submit command line;
tracked files stay site-free.

1. Create the venv under the user's own project dir from the site Python
   (Anaconda3/2023.09-0 module, Python 3.11.5) and install
   `env/leap-v1-gpu-runtime.txt`; record versions, download and disk usage.
2. Deploy a versioned bundle (`src/`, the smoke tool + sbatch, the v1 asset
   manifest and the 14-file asset cache) into the user's own task dir and
   verify every sha256 before submission.
3. Write a pre-submission receipt, then submit exactly one job:
   `sbatch --account=<ACCOUNT> --partition=<PARTITION>` with
   `LEAP_V1_GPU_VENV`/`LEAP_V1_GPU_WORKDIR` exported; record the job id.
4. On completion, collect raw outputs, confirm final job state and resource
   release, and file a sanitized draft record (accounts, nodes and private
   paths removed) for coordinator integration.

Evidence boundary: a green smoke proves the runtime and the unmodified v1
model run on one H800 at 1/32 worlds. It is not training, not task
performance, and not evidence for any larger world count.
