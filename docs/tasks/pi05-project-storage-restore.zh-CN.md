# π0.5 检查点经项目存储恢复

2026-11-02 HKT。上一项 CPU 恢复在准入检查时确认所选 CPU 节点看不到 scratch 检查点，而项目 NFS 可访问。本合同改变存储路径，保留原始检查点、原完整状态指纹、CPU 后端和所有恢复判据，不重复失败的路径。

## 资源与执行

1. Kimi 实现有界文件复制器与仅改变检查点位置/文件系统判据的恢复启动器，协调者独立审查后冻结源码。旧许可已用完，必须新建并绑定新许可。
2. 只复制已保存的 step-1 检查点：53 个普通文件、31,147,685,638 字节。源目录及所有文件只读；新目标必须不存在。不跟随符号链接，不覆盖、删除或自动恢复部分副本。
3. 文件传输最多一次，顺序复制、8 MiB 缓冲；复制总量上限 32 GiB，启动前目标文件系统至少空闲 34 GiB，采样 RSS 上限 512 MiB。内部 300 秒截止，外层 310 秒加最多 10 秒清理。此步骤仅文件 I/O，不加载模型或在登录节点做模型计算。文件系统空闲量不是独立磁盘配额证明；写入或同步失败明确中止。
4. 复制前后核对所有相对文件路径、大小、源 mtime 及两个提交元数据散列。记录确切文件字节数、耗时与失败。复制完成仅表示待恢复副本已准备，不能宣称完整数据一致；最终由原完整状态指纹验证。
5. 复制副本与最多 8 MiB 的恢复日志目录分离。最多一次 CPU 恢复作业：2 个请求 CPU、最多 4 个可见逻辑 CPU，数值线程 2；128 GiB 内存请求、120 GiB 采样 RSS 上限，300 秒墙钟、270 秒内部截止加 10 秒清理；0 GPU、0 优化器调用。
6. 仍先运行小模型模板一致性检查，再核对完整抽象模板，恢复后比较全局及全部 156 叶的原指纹。失败保留证据，不抽样、降精度、重新初始化、跳过叶或修改指纹算法。

此路径不增加首轮 GPU smoke 预算，GPU 用量仍为 1,761/1,800 秒。通过只能证明完整检查点 CPU 恢复后的状态一致；GPU 重放、正式训练和精确闭环控制分别验收。新的副本若未通过验收，继续保留原始检查点作为唯一已核实保存来源。

## 实际验收

一次文件复制完成：53 文件、31,147,685,638 字节，116.075 秒，峰值 RSS 33,688 KiB。22 项复制器边界检查通过；协调者再次核对目标目录清单、元数据、原目录未变与复制进程退出。[复制审计](../../experiments/records/pi05-project-checkpoint-copy-accepted-20261102.json)。

随后唯一 CPU 作业在 136 秒完成，2 CPU、0 GPU，资源已释放。小模型模板和完整抽象状态均通过；实际恢复耗时 82.027 秒，全部 156 叶、40,241,206,480 字节状态的原算法指纹校验耗时 30.788 秒。全局与所有逐叶散列、形状、类型、顺序及字节数完全一致，完整指纹字典相等。原保存步数为 1；读取后副本清单和提交元数据未变。协调者独立审计 22 项通过。[恢复审计](../../experiments/records/pi05-full-checkpoint-cpu-restore-accepted-20261102.json)。

这证明磁盘保存的完整训练状态可在 CPU 恢复，不证明 GPU 续训或第二步重放。该许可已消耗，不重复提交。GPU smoke 预算仍为 1,761/1,800 秒。下一项优先做显式双屏幕输入的真实 OpenPI 验证，再接入训练损失及推理采样器；动作时间尺度适配继续单独验收。
