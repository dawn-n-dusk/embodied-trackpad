# V1 第一批候选数据审核与小策略入口

四个固定方向的教师控制已通过。当前仅授权最多 12 个不同目标类别的全新试采回合；这远少于正式数据规模，只用于验证首条数据和学习管线。具体采集、打包和训练实现交给 Kimi，协调者独立核验。

## 事先冻结的分组

当前近目标 GUI 用 `seed modulo 12` 决定目标偏移类别。不能按不同 seed 或相邻视频帧随机切分：它们可能对应同一目标。以下分组在新试采之前冻结；后续派生 seed 必须继承目标类别的分组。

- 训练目标类：0、2、3、5、6、8、9、11，覆盖四方向的 12/24 px 距离。
- 验证目标类：1、7，即其中两个方向的 18 px 距离。
- 测试目标类：4、10，即另两个方向的 18 px 距离。

已参与控制器诊断的旧回合保持 development/calibration 用途，不自动并入新的训练集合。按整回合存储；失败、缺失、跳过和重复必须记录，不能把原有 `training_eligible=false` 改成 true 来冒充审核。

## 数据审核

1. 核对采集前 manifest、源码/模型/native 散列、种子/目标类/分组、运行身份、资源和完整退出。原始失败证据保持不变。
2. 验证每张 PNG 的散列、解析尺寸和图像特征，记录实际采样帧、单独的截图时钟与仿真时钟、图像消费所对应的物理步。不能把 wall time 当 sim time。
3. 每张动作前图像及其本体状态，对齐之后真实执行的 25×16 关节参考块（每物理步 2 ms）；不得把名义 endpoint 当实际标签。成功终帧没有后续动作，不造填充标签；任何 padding 必须有 mask。
4. 检查状态/动作单位和命名顺序、每步安全与接触、touch/ack、终止和离板。任何单步错位、未来信息或缺失必须拒绝该样本并给出原因。
5. Actor 候选输入只包括屏幕像素、从像素推得的特征、本体状态与过去实际控制。仿真接触力、Jacobian、oracle 坐标和结果标签保存在教师/评估侧。未安装 FSR 使用缺失 mask，不能伪造零读数。
6. 汇总样本数量、动作/目标分布、重复与缺失、各组目标类，以及完整性检查。另建派生数据清单明确允许用途，保存原始 false 标记及其出处。大图、原始会话和账户路径不进入公开仓库。

当前记录保留了因果步索引和观察时的状态，但跨时钟不确定度、动作标签粒度与缺失传感器字段仍须在实际数据审核中明确；不能把源码测试替代这一步。

## 后续小策略 smoke

审核通过后才冻结小策略结构、损失、动作限幅、数据散列、独立测试目标和停止/恢复标准。先验证真实优化器更新、保存/恢复完整 checkpoint，再在冻结测试目标上执行学习策略，通过同一物理与 GUI 链路评估。测试成功必须由实际图片、触点和安全退出证明；训练 loss 下降不能替代任务成功。

首个 GPU smoke 保持既有上限：1 张 H800、最多 64 环境、30 分钟，实际申请与进程身份逐次核验。是否需要并行物理环境取决于该次训练方法；离线 BC 不能被描述成几十个交互环境。小策略是工程基线，后续 π0.5 全量微调路线保持不变。
