## 目标与范围

将 LEAP v1 简化右手模型作为可选资产接入，目标硬件为 Full/XC330；保留现有 Allegro 场景。第一阶段仅检查模型来源、许可、可编译性和手指运动，输出可复核的导入记录，不切换当前推流/服务。

先读 AGENTS.md、README.md、STATUS.md、architecture.zh-CN.md 及 ADR 0005。

建议允许文件：`models/leap_v1/manifest.json`、`models/leap_v1/README.md`、`tools/leap_v1_import.py`、`tests/test_leap_v1_import.py`、`docs/experiments/leap-v1-import.zh-CN.md` 和独立实验记录；原始下载、编译产物与运行图放在忽略目录。若既有模型加载接口更适合，先在短检查点中提出具体文件范围再继续，避免另建重复仿真框架。保留上游许可与归属，不提交私人路径/截图/会话。

## 第一阶段验收

1. 固定上游提交和所需文件清单/哈希；验证许可，下载内容不得执行任意脚本。初次只取需要的手模型，避免下载完整 Menagerie 或训练权重。
2. 用现有 MuJoCo CPU 运行时编译；导出实际 `nq/nv/nu`、关节/执行器顺序、范围、指尖标识、碰撞与传感器清单。期望手为 16 个主动关节，但以实际编译清单为准。
3. 通过执行器参考做有界的单指屈伸、侧摆和两指间距变化；不得逐步直接覆写 `qpos` 来伪装控制。记录请求控制、实际状态与接触。
4. 保存固定机位的初态与运动图、模型/控制参数哈希、实际执行命令和失败项，由协调者独立视觉复核；“编译成功”与“触控板可用”分别报告。
5. 对来源完整性、参数/索引匹配和无效模型拒绝做必要检查；不为只读取字段增加镜像实现的测试。

拟定执行上限：单次不超过 15 分钟、CPU 资源，模型下载不超过 100 MiB；实际调度时明确使用的主机和解释器。没有新增 GPU 分配，也不运行策略训练。缺少运行时或越过预算时保存检查点，交回协调者重新界定，不自行扩展。

## 后续阶段，未包含在第一阶段

与现有 7 轴机械臂、160×110 mm 板面组合；校验安装变换和碰撞；验证单指接触/释放、两指持续接触变距、滑动和板边重定位。重新生成此手的教师控制，不复用 Allegro 的关节向量或策略权重。之后再复核 MJWarp/H800 与 GUI 接入。完整动作维数预期 7+16=23，但相同维数不代表相同语义。

不得更改真实 Mac/VM、推流部署、NexArm/Jetson/串口设备或外部服务，不安装硬件驱动，不采购，不提交/推送 Git。不得把旧 Allegro 的 GPU 结果标为 LEAP 结果。

回报仅包括文件、模型清单、实际检查/命令、证据路径、失败和未验证项；不要导入整段原始模型会话。源码与结果由协调者验收后再切换主研究环境。
