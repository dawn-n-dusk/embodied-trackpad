# 双屏幕路由的真实 JAX CPU 验证

2026-11-02 HKT。双图输入已通过官方 CPU 变换，损失与采样路由已通过源码和替身测试。本任务验证这些函数在真实 JAX 编译、自动微分、更新闭包及积分循环中的行为。

使用固定官方 OpenPI、JAX、Flax、Optax 运行时，以及明确标注的微型合成 NNX 模型。它只复现调用接口和可微张量运算，不创建完整 π0.5，也不加载机器人权重。必须记录诊断模型的实际参数数和更新次数；完整预训练模型仍为 3,353,433,872 个可训练参数，既有检查点不变。

## 验收内容

- 真实 `jax.jit` 中的双图预处理保持像素、状态、token 和 mask；主机侧错误字段拒绝测试与编译内检查分开记录。
- 生产有效 16 维 Flow Matching 损失的 eager／JIT 数值与梯度一致、有限；直接解析检查 padding 维度的损失梯度为零。
- 生产 `build_full_update(screen_pair)` 在正常输入上真实更新，step 和随机状态正确推进；在非有限输入上拒绝，全部参数、优化器、step、随机状态保持不变。复制待比较数组后再调用捐赠状态的编译函数。
- 生产采样器的 eager／JIT 与独立 Python Euler 参考一致；固定噪声、生成噪声和两个积分步数分开核对。诊断模型必须实际使用图像、掩码、位置、KV 和条件输入，避免恒定输出掩盖路由错误。
- 保存小型原始数组、形状／类型／散列、数值误差、参数普查及失败位置。协调者独立核对，不能只依靠检查布尔值或退出码。

## 资源与执行

Kimi 准备诊断源码；协调者审查后绑定新许可，再由 Kimi 运行一次 CPU 作业。最多 2 CPU、4 个可见逻辑 CPU、16 GiB 内存、2 个数值线程、180 秒调度时限、150 秒内部时限和 10 秒清理宽限；产物最多 16 MiB，0 GPU。只使用现有运行时，不安装依赖、操作真实硬件或个人桌面，也不在登录节点计算。

提交前核对作业、进程身份和已有检查点。新源码清单必须包含共享布局模块；旧源码包、许可、失败证据不修改或复用。失败保存证据，先判断实现、诊断或环境问题，不能自动重复同一配置。

本任务通过仅建立真实编译与更新机制的正确性。微型模型对图像扰动有反应，也不代表完整 π0.5 已学会触控。完整模型的新布局执行、GPU 续训／重放、20 ms 动作时间尺度与闭环精度继续分别验收；不增加已用 1,761/1,800 GPU 秒的首轮 smoke 预算。

## 最小模块拆分

首个诊断源码准备调用在 240 秒超时且未保存源码，未提交作业。保留回执与用量后，先将模块 A 缩小为真实 JIT 双图预处理和有效 16 维损失的解析梯度检查；不构造诊断模型、执行优化器或采样器。模块 B 再验证微型 NNX 模型上的 Flow Matching 和更新闭包；动作采样单列为 C。各模块独立记录通过范围，不能把 A 通过当成 B 或完整模型通过。

## 模块 A 实际结果

单次 CPU 作业完成，调度占用 11 秒、2 CPU，共 22 CPU 秒；峰值 RSS 897.93 MiB，0 GPU、0 模型参数、0 优化器更新。77 项实际运行检查通过，协调者核对 26 个数组并通过 89 项独立检查。JIT 前后像素误差为 0；有效 16 维自动微分梯度与独立 float64 解析参考最大差 2.98×10⁻⁸，补齐通道梯度严格为零。

标量损失的 JIT／NumPy 差为 3.81×10⁻⁶，在运行前冻结的 float32 误差范围内。字段顺序的拒绝测试在主机 eager 路径进行；JAX 将字典展平时会排序，不能声称编译内部保留了原插入顺序。[实际验收记录](../../experiments/records/pi05-screen-routing-jax-gate-a-accepted-20261102.json)。

这是真实编译与损失函数自动微分的验证，尚未运行 Flow Matching、模型参数更新或动作采样器。模块 B 的微型 NNX 源码准备继续单独进行；完整 π0.5 的能力不从这些诊断外推。

模块 B 首次准备在 240 秒超时，但源码已保存。审查发现构造、张量形状、梯度返回顺序及捐赠状态复制问题，尚未提交计算。保留该版本后，将 B 缩小为 Flow Matching 和一次更新／拒绝检查；动作采样单列为 C，避免在同一诊断里混合多个尚未通过的模块。

## 模块 B 的实际失败与下一项诊断

单次 CPU 作业在 21 秒后以失败结束，2 CPU 共 42 CPU 秒，0 GPU；峰值 RSS 1,163.51 MiB。53 项驱动准入检查通过，但真实 eager／JIT 梯度对比未通过运行前冻结的 `rtol=1e-5, atol=1e-6`。11 个参数路径一致；实际差值和对应参数尚不可知，因为用例在返回原始数组前抛出了断言。优化器阶段尚未到达，驱动报告的更新次数保留为 null，不改写成已量测的零。

保留旧源码、许可、错误与终态，不原样重交，也不放宽容差。下一项缩小为纯梯度诊断：分别保存 NNX eager、pure eager、pure JIT 的全部梯度及逐叶误差，先保存数组再判定失败，定位是编译数值误差、测试实现还是实际路由问题。更新／拒绝和 C 采样器尚未通过。[失败记录](../../experiments/records/pi05-screen-routing-jax-gate-b-gradient-failure-20261102.json)。

更小的三路径梯度用例已完成源码修正与 14 项独立源码／NumPy 检查：保存所有参数路径，形状不匹配时保留数组并报告失败，JIT 只返回数值 pytree。[源码记录](../../experiments/records/pi05-gradient-evidence-diagnostic-source-20261102.json)。它尚未在 JAX 中运行；新的 CPU 驱动必须先保存失败报告和全部数组，再返回非零退出码。此前失败及容差不变。

本轮共 13 次 Kimi 调用，累计调用时间 1,943.6 秒；2 次超时和 1 次 OAuth 网络失败已保留，重连成功。实际计算为两个 CPU 作业，合计 32 秒调度占用／64 CPU 秒，0 GPU。调用时间与计算时间不同；[用量与返工记录](../../experiments/records/kimi-screen-routing-jax-usage-20261102.json)包含 323,554 非缓存输入、15,919,616 缓存输入及 98,455 输出 token，不作为会员额度或计费金额。

## 三路径梯度差异已量化

13 秒 CPU 诊断保留 45 个原始数组，143 项独立核对通过。NNX eager 与 pure eager 的全部 618 个梯度元素完全一致；跨 JIT 比较有 2 个元素、2 个参数叶超出原 `rtol=1e-5, atol=1e-6`，最差为阈值的 1.12184 倍。整体相对 L2 差为 9.73×10⁻⁸，三个损失值均为 64.00735473632812。原门槛仍失败，作业按设计以 `FAILED/2:0` 结束；这里只接受证据采集和差异定位。[独立记录](../../experiments/records/pi05-gradient-isolation-observed-20261102.json)。

下一次检查在**相同 JIT 编译条件下**比较 NNX 与 pure 求导，容差不变。该比较通过后才执行一次生产更新和同一更新状态上的 NaN 拒绝检查；旧的 eager／JIT 差异单独保留，不追认通过。这样区分求导接口一致性与跨编译数值变化。具体编译优化原因仍未证明；完整模型结果也不能从微型诊断外推。新源码和单次 CPU 合同须先审查。
