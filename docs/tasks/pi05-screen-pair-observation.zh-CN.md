# π0.5 显式双屏幕视图输入

2026-11-02 HKT。原像素裁剪已通过独立软件和两张真实图像检查。本任务将全屏和局部图放入明确的 Observation 字段，保留缺失腕部相机的事实，不复用腕部名称表示屏幕图。

| 字段 | 内容 | 有效性 |
|---|---|---|
| `base_0_rgb` | 当前完整屏幕，经已验收官方等比例缩放至 224×224 | 当前输入有效 |
| `screen_local_0_rgb` | 同一帧光标附近 224×224 原像素图 | 继承像素检测和裁剪有效性 |

新布局只有这两路图像；腕部相机缺失信息单独保留为 false 的传感器来源记录。局部图边缘的逐像素 padding mask 不等于模型图像级或 token 级注意力 mask。无效局部图在原始 uint8 空间置零，经官方缩放规则后为 -1，图像有效 mask 为 false。

复用原构建器的 tokenizer 校验、16 维归一化状态 tokenization、32 维 padding、有效 16 维损失 mask 和全图缩放，不改变标签、参数或权重。新增视图的坐标只来自当前 RGB，不接受 GUI API、评分器、未来帧或标签坐标。

固定的 OpenPI 版本中，`preprocess_observation` 允许显式 `image_keys`，但默认值仍为三个相机字段。新的主机侧入口必须传入精确两路屏幕字段、关闭增强并验证两路均保留。图像编码器遍历实际保留的图像，不能仅在字典里加入局部图就声称模型已使用它。

## 验收边界

- 软件测试可验证字段、像素缩放、mask、原状态/动作/token 保持和错误输入拒绝；使用依赖替身的测试不能替代真实 OpenPI 运行。
- 主机侧入口包含 NumPy 和 Python 条件检查，不能直接放进 JAX 编译或求导函数处理 tracer。后续训练入口应在主机侧完成验证，并在编译内部显式选择固定布局。
- 现有有效 16 维损失和官方动作采样器仍走默认三相机预处理。本任务不修改它们；训练和推理路径接入要单独审查，不能只改训练路径而遗漏推理路径。
- 缺失腕图不伪造。新布局不增加可训练参数，但模型真实吞吐、精度、动作时间尺度和 checkpoint 兼容性仍须实际验证。

## 软件验收

新模块与原 Observation、局部视图、视觉工具的组合测试共 138 项独立通过。最终图像诊断字段与真实双视图一致，状态和 token 数组单独复制；真实 OpenPI 运行及编译损失/采样器接入仍待验证。[审查记录](../../experiments/records/pi05-screen-pair-observation-reviewed-20261102.json)。
