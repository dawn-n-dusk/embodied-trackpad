# π0.5 的 20 ms 动作窗口与后续 GPU 恢复

2026-11-02。双图预处理、更新机制和采样器的限定 CPU 用例已通过；完整模型仍保留原生 2 ms 标签的 step-1 检查点。下一步优先把已审核的原始动作拼成明确的较长时间窗口，同时准备完整模型 GPU 恢复及双图评估合同。不得重复已通过的 CPU 检查来代替推进数据与模型。

## 首个实现模块

Kimi 先检查已审核原始语料的时间连续性，复用 `action_resampling.py` 的纯数值函数，增加独立的时间窗口组装模块与必要边界测试。第一批只读既有语料，不采集新数据，不连接 GUI、硬件或个人桌面，不安装依赖。

- 候选窗口包含 250 个连续的 2 ms 原生控制区间，构造 25 个 20 ms 控制参考，覆盖 0.5 秒。保留 16 维绝对执行器位置命令及弧度单位，不误换成关节增量或实测关节位置。
- 先核对原始索引、实际控制时间戳、窗口半开区间与前一控制的含义。明确区分原生命令的生效区间和新参考的区间终点；不得直接把第 9 个原生样本的记录时间改写为 20 ms。原始时间戳保留，新参考时间单独记录。
- 同一回合内必须有完整覆盖。重叠数据须验证命令一致并保留来源；缺口、冲突、回合／reset／split 边界、时间非单调和不足长度必须拒绝或计为不足样本，不插值跨越缺失记录，不补造动作。目标／控制阶段是否允许跨越需在检查实际记录后明确，不能静默混合。
- 观测使用动作起点之前已可获得且有来源绑定的图像与本体状态；保留图像采集／接收、模拟动作时钟及帧龄的区别，不把未来截图用于当前输入。没有短历史就保留单帧，不伪造视频序列。
- 调用既有数学重采样函数，记录逐回合／逐通道数值重建 RMS、最大误差、控制跳变与常量通道。数值重建误差不等于真实动力学轨迹误差，必须留待独立回放验证。
- 训练／验证按已冻结的完整回合划分；先报告可组装、拒绝与不足窗口的真实数量，再决定小批规模。不得把重叠窗口当成独立回合扩大样本量。
- 原生 `VisualExample`、`Pi05NativeSample` 与旧检查点时间含义保持不变。新窗口使用显式格式／版本和 provenance，后续单独适配 OpenPI。归一化只从训练集计算；缺失传感器与有效 16 维 loss mask 继续保持。

协调者先审查小型组装模块，再由 Kimi 用既有轻量运行时验证合成边界与少量真实窗口；本地每批最多 10 分钟、2 CPU 数值线程，先不申请 GPU。独立核对至少覆盖连续段、缺口、冲突、reset、split、观测因果性和原生标签未被改写。若实际语料没有足够连续覆盖，保留不足结论并据此设计新的有界仿真采集，不绕过约束。

## 完整模型的下一项合同

并行准备的下一份 GPU 合同应明确：从完整 step-1 状态恢复，使用已审核双图输入，保存采样输出与有限更新／新检查点，记录实际模型总参数和可训练参数。原生时间 smoke 与 20 ms 新数据训练分开；不得在原生检查点上静默更换动作时间含义。

当前首轮 smoke 已用 1,761/1,800 GPU 秒。此文件不自动追加或重置预算，也不签发作业许可。后续须在现有“单次最多 1 H800／2 小时、滚动 24 小时最多 6 GPU 小时”的上限内，形成源码、输入、恢复、保存、停止条件和实际资源都可审查的独立合同，再执行。不得把 CPU 机制通过称为完整模型 GPU 恢复、视觉精度或长程任务完成。

提交前使用精确的检查点目录核对库存。调度提交意图与返回 job ID 应持久保存；SSH 回执不明确时，交由协调者核对调度历史与运行目录后再决定，不能仅凭一次空队列重复 `sbatch`。

## 20 ms 时间窗口已完成离线验收

2026-11-02：新模块在原索引不变的前提下，把 250 个连续 2 ms 控制区间组装为 25 个 20 ms 端点参考（0.5 秒），保留 16 维绝对执行器位置命令和当前真实图像。两套语料合计 1,044 个窗口：训练 599、验证 250、测试 195；180 个末尾起点因覆盖不足被排除。110 项相关测试和 93 项独立数组／图像／来源核对通过。实测整批数据审核约 0.409 秒；不需要额外 GPU。

这仍是 20 个教师回合、61.2 秒原始动作，重叠窗口不增加独立回合数。仅前 4 个通道变化，其余 12 个通道固定；没有多指手势训练数据。独立核对全部窗口的逐通道总体 RMS 和全局最大重建误差，最大值为约 0.000935 rad；这是命令重建的数值误差，不是物理跟踪或光标误差。原报告的“max”统计是窗口最大值的均值，不能替代全局最大值。原数据缺少 phase/goal/reset 显式标注，保留来源限制，不推断阶段覆盖。
