# 20 ms 动作窗口的模型输入适配：下一阶段合同

2026-11-02。接续独立窗口统计量拟合；本合同不启动训练，也不改变现有 2 ms 检查点的含义。

## 分离时间语义

当前原生链是 25×2 ms；新链是 25×20 ms。两者张量形状相同，仅检查形状不能防止误用。新链必须使用单独的 `Pi05WindowSample` 类型和严格时间／格式版本验证，不能把粗窗口伪装成 `Pi05NativeSample`，也不能修改时间字段后绕过已有验证。

旧原生归一化入口只检查其既有统计来源约定，不提供新窗口格式的自动隔离保证。因此本阶段拟合结果仅供新入口使用；在新的类型、时间、来源约束验收前，不接入任何模型调用。已冻结的 GPU 恢复包仍只使用原生输入。

## 小模块顺序

1. 从公共 `load_window_observation` 返回值构建独立窗口样本。保留当前起始帧、原始关节状态、25×16 绝对粗参考、20 ms 端点时序、完整窗口来源及缺失传感器掩码。不得读未来图像、oracle 坐标或教师配置。动作转换为 float32 时显式记录舍入；原始 float64 标签仍保留。
2. 新的归一化应用入口验证 `leap-v1-pi05-window-norm-v1`、train-only 来源、语料／索引绑定、0.002/0.02/25/0.5 时间合同、绝对弧度语义以及所有数值。复用公式语义 `(x-q01)/(q99-q01+1e-6)*2-1`，不重新拟合、不裁剪、不伪造常量通道方差；返回独立副本及常量／范围外报告，拒绝二次归一化。
3. 在上述接口通过后，接入官方全屏＋局部原像素视图、16 维状态 tokenization、32 维 padding 和 valid-16 loss。视图掩码、时间和归一化身份始终随样本保存。旧原生入口及冻结源不随手改写；若需要共用代码，先保存其冻结源快照，再独立审查兼容性。
4. 至少两个真实起始样本做标签、当前图像、状态和掩码独立对照；再安排有界 OpenPI 运行时检查。GPU 续训恢复合同和本数据转换合同分开验收。

## 检查和预算

先检查正确样本、旧时间／旧统计量拒绝、来源不匹配、非有限值、常量通道、重复归一化和副本隔离。采用小批验证，不因样本切片量大就扩大测试。每次本地数值批次最多 10 分钟、2 线程、16 MiB 小型产物；运行时 GPU/Slurm 使用单独许可。

已保存 step-1 检查点对应旧动作尺度及统计量。未来新窗口训练必须另立数据／统计量／动作时间的训练谱系；不得将它称为旧实验完全相同的恢复。无论权重是否复用，均记录起点、实际更新和独立闭环评估。20 段教师轨迹的重复切片仍不构成新的独立演示；数据覆盖和控制精度另行验证。

## 原始窗口样本接口细化

窗口模块保留的动作名称为 `absolute_executed_actuator_command_rad`，已有统计量采用 `absolute_executed_joint_reference_rad`。它们在这条 LEAP v1 的 16 通道数据链中都指实际执行的绝对位置参考。新样本必须同时保留来源名称和模型规范名称，显式记录名称映射；数值、单位、通道顺序不变，增量动作不得混入。

第一模块为独立 `Pi05WindowSample` 与 `prepare_pi05_window_sample`：只从已验证 `WindowObservation` 取当前图像、本体状态和粗动作参考，保留 float64 标签，显式记录转为 float32 的舍入误差。验证 25 个端点与原起始状态之后的 20 ms 时间轴一致；原生 2 ms `action_window` 留作来源记录，不重写。此时归一化、padding、缩放和 tokenization 均仍待执行，不能称为模型输入已完成。
