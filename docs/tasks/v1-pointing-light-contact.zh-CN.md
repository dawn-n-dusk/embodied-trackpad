# 避免意外点击的轻触教师候选

斜向教师四回合中三个满足原定位判据，第四个在一次点击完成后把靶标显示为绿色，固定蓝色定位器随即按原规则停止。原生设备按压力≥1.0N按下、≤0.6N释放；原教师切向运动直到1.1N才完全抑制。这暴露了定位任务与点击状态之间的冲突。历史结果不改判，不能通过关闭点击、保持靶标蓝色、放宽视觉门或提高物理门槛解决。

只试一个小改动：新增明确命名的pointing-light接触模式，将切向停止力从1.1N改为0.9N；法向目标仍0.8N，其余增益、动作限制、P1准备、物理安全门、GUI设备阈值、视觉定位和成功/释放判据不变。0.9N是未校准候选，不保证实际接触力不会越过1.0N。默认standard模式保持原行为。

源码只修改既有教师runner和对应stub测试。CLI增加--contact-mode standard|pointing-light；pointing-light只允许force-governed规划器，run与CLI在输出/环境/应用之前验证。所有实际compose_governed_substep调用使用同一选定配置，metadata与summary记录模式和完整配置；旧调用默认兼容。不要增加新的GUI字段、传感器、坐标API、在线学习或通用调参接口。最多180秒、2数值线程，仅运行纯静态/stub测试，独立验收后才冻结运行许可。

随后仅对失败的near_diagonal_v1 seed3运行一次新配置，不补跑旧配置，不把它与前三个旧配置结果合并成同配置4/4。每回合最多120秒墙钟、20秒仿真、120图像、60MiB；保留全量接触/控制/触点和PNG。按原定位判据评分，同时独立报告全部物理子步和发给设备的触点帧是否越过1.0N、是否出现按下/释放或绿色点击反馈。轻触候选只有同时满足原成功条件、GUI连接后的控制及释放阶段均无按压阈值越界，才可进一步扩到其他方向。失败保留，不继续盲扫；若切向限幅不足，再依据记录决定是否需要单独的接触稳定准备阶段。

本实验为教师数据来源诊断，不是学习策略改进。学习actor、既有训练集和权重保持冻结；新数据仍training_eligible=false，需另行审核再训练。真实硬件、个人桌面与GPU不在本任务范围。
