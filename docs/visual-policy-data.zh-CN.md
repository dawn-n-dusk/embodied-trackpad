# 视觉策略数据接口的当前边界

2026-11-01。真实 RGB 数据模块已由 Kimi 实现并经独立检查；这为完整预训练 π0.5 与视觉时序对照准备输入，尚未加载或训练更大模型。

`VisualCorpus` 分别读取既有直线与斜向索引，核对整个索引散列并复用原始切分校验。1,224 个动作块仍属于两个独立语料，共 20 回合；不会因同号 episode/target class 混淆身份。模型观测只包含完整的 800×600 RGB 像素、q/dq/上一控制和缺失传感器标记；二维颜色定位结果、目标类别和教师信息不进入 actor。

动作标签独立存放，保持实际执行的 25×16 绝对关节参考，步长 2 ms、总长 50 ms。没有把这些标签改名为 20 ms，也没有补齐成 OpenPI 默认 32 通道/50 步。PNG 路径限定在证据根目录内，检查散列、尺寸和透明通道，不裁剪、不缩放、不伪造腕部图像。

独立验证包括 23 个边界测试，两个完整索引的结构/划分，以及分布在训练、验证、测试首尾的 12 张真实图片。逐像素核对 RGB、逐元素核对本体/动作、确认输入排除教师字段，并检查返回数组修改不影响下一次读取及原始文件。集成后同一组 23 个测试通过。Kimi 调用虽在 600 秒时超时，但已保存源码、测试和实际数据回执；这些文件经独立检查后才被接受。

当前只有单帧观测和原生短动作块。下一模块在不跨回合/切分、不读取未来图像的条件下构建更长目标窗口，明确 20 ms 控制参考与 2 ms 物理步之间的重采样/插值关系，补全捕获时钟信息。OpenPI 数据重排、有效维度处理、归一化与原生时间标签的模型 smoke 可并行推进，较长动作块单独验收。个人 GPU 运行环境按实际环境核查，避免把本机某个 Python 缺包误判成服务器没有 PyTorch。

局限：当前索引仍来自只包含少量 GUI 指向任务的已审核教师数据，不能证明通用界面、点击、拖动或长程学习能力。未来其他外观/恢复任务需要新的采集与索引规则。完整记录见 [接口验收](../experiments/records/visual-corpus-module-accepted-20261101.json)。

## 首次大模型检查与后续执行时间分开

完整时间窗口模块本次在 600 秒截止时没有保存代码或测试，不能验收。已保留回执与用量，并将下一任务缩成纯数值重采样函数。它完成后仍须接入连续回合标签、时钟与切分检查，才能用于 20 ms 控制参考。

首次 π0.5 加载、前后向和更新检查可以先沿用已验收的原生 `25×16`、`2 ms` 标签，并将模型动作 horizon 明确配置为 25。它检验模型和数据训练接口，不表示 2 ms 神经推理，更不直接用于闭环执行。较长动作块、插值和滚动重规划单独验收，避免为了准备长窗口而阻挡完整预训练模型接入。

OpenPI 官方提交固定为 `215abfb217dbac7d5f1273282331b9b1866c0479`。现有项目环境元数据为 Python 3.11.5、PyTorch 2.8.0；固定上游要求 PyTorch 2.7.1、NumPy <2。这需要独立环境，不能覆盖旧的可恢复运行环境。新环境准备已委派；不能把成功的 SSH 查询当作依赖安装通过。官方基础检查点对象清单共 29 项、12,441,749,581 字节，目前只核对清单，尚未下载或加载。

官方默认模型为 32 维动作；仍需显式处理 16 个有效关节、归一化和动作损失。固定 PyTorch 实现返回逐动作维损失，可由训练包装器选择有效维度；固定 JAX 实现先对动作维求均值，不能仅增加一个未使用的 mask 就声称忽略 padding。缺失腕部图像必须保持无效，不能把屏幕副本当作真实腕部相机。

参见 [环境元数据与超时恢复记录](../experiments/records/pi05-runtime-metadata-and-temporal-recovery-20261101.json)。尚未有 π0.5 前向、参数量实测、优化器或闭环成绩。

重采样计算函数随后已验收：22 项测试、6 段真实标签的独立 `numpy.interp` 对照及主仓库复测通过。它从每 10 个原生参考中取第 10 个端点，并计算线性重建差异；6 段各覆盖 250 个原生步。该结果只证明数值转换正确，仍未证明接触运动等价，也未实现跨行时间窗口的完整数据校验。见 [数值模块记录](../experiments/records/action-resampling-math-accepted-20261101.json)。
