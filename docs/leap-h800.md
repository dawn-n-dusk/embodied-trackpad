# LEAP v2 Advanced：H800 批量后端验收

完整 17 电机、21 关节 LEAP 手已在实际分配的 NVIDIA H800 上运行。修正后的作业正常完成，用时 7 分 46 秒，42 项检查通过，依次运行 1、32、128、512 个世界。每个世界执行与 CPU 相同的 14,000 个控制参考，共 7 秒仿真时间；四档合计 9,422,000 个世界步。

这是手部脚本回放的后端检查。触控板接触在 CPU 上单独验收；本次 GPU 运行没有板面、GUI、策略训练或不同任务的随机采样。可复核结果、源码哈希和检查覆盖见[实验记录](../experiments/records/leap-h800-20261031.json)。

## 配置与测量

同一官方资产、转换器、模型参数、初态和控制序列；保留四组耦合及全部碰撞设置。运行环境为 MuJoCo 3.17.0、MuJoCo Warp 3.17.0、Warp 1.18.0、NumPy 2.2.6。一张 H800、八 CPU、每个作业最长二十分钟；成功作业已结束并释放分配。

| 世界数 | 完整序列耗时 | 合计世界步/秒，包含下发与检查 | CPU/GPU 最终最大关节位置差 |
|---:|---:|---:|---:|
| 1 | 99.175 s | 141 | 1.42×10⁻⁷ rad |
| 32 | 94.680 s | 4,732 | 1.42×10⁻⁷ rad |
| 128 | 108.834 s | 16,465 | 1.42×10⁻⁷ rad |
| 512 | 152.508 s | 47,001 | 1.42×10⁻⁷ rad |

512 世界的采样耦合残差最大约 0.00809 rad，限位偏差为零，世界 0 采样穿透最大约 0.449 mm，最终开手误差约 0.0371 rad。所有世界最终状态有限，最大跨世界关节位置差约 1.49×10⁻⁸ rad。

上述主耗时包含 Python 循环、控制传输和观察回读，编译/预热单列。减去观察耗时得到的数值仍包括主机循环和控制下发，不能称为纯 GPU 内核时间。目前程序用于正确性检查，还不是经过吞吐优化的训练采样器；没有测量端到端训练加速或 CPU 批量实现的性能。

## 初态检查修正与覆盖限制

第一次作业运行完单世界后，原始浮点字节哈希检查失败，因此停止扩大批量。CPU 初态为 float64，GPU 数组为 float32；将相同初态精确转换成 float32 后，哈希与首次 GPU 记录一致，转换误差最大为 7.45×10⁻¹⁰。失败作业保留在[先前记录](../experiments/records/leap-next-validation-first-failures-20261031.json)。

新检查对步进前读取的每个世界、每个状态/控制字段验证：GPU 数组必须精确等于按其实际浮点类型转换后的 CPU 初态。没有放宽关节、耦合、碰撞或 CPU/GPU 位置差门槛。22 项专项测试检查源序列、初态、单字段/单世界/单浮点单位扰动及输出保护。

世界 0 的关节与接触每 20 步及末步采样；所有世界的状态每 200 步及末步检查。GPU 警告计数不可用，标为未知；接触/约束容量的采样峰值未超限，不代表采样间隙从未溢出。

CPU 接触在步进后通过 `mj_forward` 刷新，GPU 保存的是该求解步积分前的接触计算结果。两者接触观察时刻不同，不能把它们直接当成同一瞬间的接触真值对照。后续 GPU 接触到 GUI 的闭环需要明确自己的观察时序。

## 复现入口

先按[模型指南](leap-model.md)获取固定版本资产。程序为 `tools/leap_h800_probe.py`，通用 Slurm 启动文件为 `tools/leap_h800_probe.sbatch`；账号、分区和运行目录由本地环境提供，不写入公开仓库。`env/probe-requirements.txt` 保留已验证的 GPU 依赖信息。

使用新的输出路径；`--tiny --cpu-only` 仅验证短程序流程。正式 GPU 运行按前一档检查和剩余资源决定是否扩大到下一档。公开 CI 没有 CUDA 和仿真依赖，会跳过可选物理测试；实际本地/GPU运行证据与 CI 成绩分别记录。
