# 独立 Mac 测试台

> 2026-10-31 最新安排：未来测试设备可为 MacBook 内置触控板，也可为独立 Apple Trackpad；不要求现在有完全闲置 MacBook，软件仿真先行。独立 Trackpad 仍需连接运行 GUI 的 Mac；型号、尺寸、增益、输入隔离和原生多点手势到位后单独校准。当前已授权的 M5/受限原生 GUI/虚拟机边界保持，详见 [ADR 0006](decisions/0006-latest-leap-and-hardware-readiness.zh-CN.md)。

用户于 2026-10-30 更新安排：M1 暂时不能专用，先使用当前 M5 Mac；优先隔离输入，允许继续实验和训练。当前机器已只读确认是 M5、16 GB、macOS 26.4.1，`VZVirtualMachine.isSupported=true`。训练和大模型推理放在 GPU 服务器。

## 当前 M5 路线

Apple Virtualization.framework 支持 Apple Silicon 上的 macOS 虚拟机。主机检查时处于内存压力状态、交换空间已使用约 14 GB；用户随后明确允许同时启动 VM，并会反馈卡顿。4 核、6 GB、固定 1024×768 的 macOS 26.6.2 guest 已启动并观察到桌面；后续输入/视频桥接的验收仍单列。此内存读数是当时的快照，当前资源与运行状态见 STATUS.md 和实验记录。

初次尝试 Tart 的实验性宿主 VNC 服务时，检查发现它监听宿主通配地址；已停止该模式并改用无宿主 VNC 服务的 guest 运行方式。guest 自身的 Screen Sharing 服务可通过 host-only 网络访问，但这仅验证了服务握手，不代表画面/输入桥接已经完成。后续由 Kimi 实施并验证 guest 输入与采集，禁止把未检查的宿主网络监听说成仅本地可达。

首个目标是本项目自己的原生 GUI：用 App Sandbox 签名限制系统资源，输入只交给自有内容视图，模型只收到该视图渲染的像素。禁止全局鼠标/键盘注入、桌面抓屏、剪贴板、文件选择、应用跳转和网络能力。主机 Python 控制器通过继承的标准输入/输出传递经过动力学产生的触点并保存图像；它不会获得一条可指定任意应用或屏幕点击位置的桥接接口。

这个原生测试应用不是完整 macOS 虚拟机，也不代表已经操作 Finder 或 Preview。签名中出现 App Sandbox 权限与实测隔离是两项证据，分别记录；尚未验收前不宣称隔离已经成立。实际触点—GUI—像素链路与人为构造的桥接 smoke 输入同样分开，后者不算训练示范。

真实系统应用实验进入 macOS guest：固定镜像摘要/系统版本，关闭主机目录共享和剪贴板共享，不登录个人账户，输入与捕获止于 guest；先验证空白测试桌面、恢复与停止机制，再开放测试文件。Tart 运行时和镜像缓存放在本项目私有目录，记录发行包校验和与签名；不覆盖其它虚拟机。原生测试 GUI 同时保留为轻量、可重置的开发与数据环境。

用户不需要现在为本项目升级主机系统、改变显示配置或开放全局辅助功能。当前测试应用应在自己的进程内渲染图像。完整桌面捕获、任意原生应用和 Apple 原生多指手势能力另行测量。

来源：[Apple macOS 虚拟化指南](https://developer.apple.com/documentation/virtualization/running-macos-in-a-virtual-machine-on-apple-silicon)、[App Sandbox](https://developer.apple.com/documentation/security/app-sandbox)、[App Sandbox entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.app-sandbox)。

## 后续 M1 独立测试机

M1 仍可作为后续独立测试端；它目前未接入本项目。以下是该设备可专用后的配置建议。

建议使用独立本地测试账户、测试文件与稳定网络；升级到设备支持的稳定系统后记录版本，在一个评估阶段内固定。8 GB 可开始轻量任务，16 GB 对多应用和较长录制更从容。仿真阶段只要求可靠网络可达，不要求机器与操作者物理相邻。

## 设备与环境建议

| 项目 | 建议 |
|---|---|
| 芯片 | M1 足够；该机器不加载 27B 模型或执行训练 |
| 内存 | 8 GB 可开始轻量任务；16 GB 更适合多应用、缓存与录制 |
| 系统 | 使用该设备支持的稳定版本；记录精确版本/build，在同一评估阶段内固定 |
| 磁盘 | 先留出约 50–100 GB 测试/缓存空间作为起点，按短时试采实测容量；长期数据及时转存服务器 |
| 显示 | 固定一个显示器、分辨率和缩放；可从约 1080p 工作区开始。M1 MacBook 的内置屏幕即可 |
| 光标 | 放大到容易跟踪且不挡住目标的大小，记录实际设置与样式 |
| 网络 | 有线更稳定，稳定 Wi-Fi 可先测试；记录图像和动作延迟，而非只看带宽 |
| 应用 | 先 Finder/Preview 等内置应用，之后逐步添加其它应用 |

M1 mini 无显示器时，需先验证它能提供稳定的图形桌面和捕获画面；SSH 登录本身不等于可用的图形会话。不需要为了仿真先购买实体机器人或额外触控板。

## 首次接入顺序

1. 由设备用户建立专用本地测试账户，登录图形桌面。使用测试文件夹和可公开图片；无需登录个人 iCloud、邮箱或社交账户。
2. 记录芯片、内存、系统 build、显示尺寸/缩放、应用版本和网络路径。系统如需升级，在正式数据批次开始前完成。
3. 在独立测试目录部署桥接程序。首次屏幕录制和必要的辅助功能权限由用户在 macOS 系统界面授权；不修改 TCC 数据库。
4. 先只采集屏幕，核对光标是否包含、帧率、时间戳、裁剪与坐标变换；不得借系统光标真值替代策略的视觉识别。
5. 在专用测试窗口启用受限输入，逐项验证相对移动、点击、拖动、滚动。记录输入的仿真触点来源及实际画面变化。
6. 检查按钮释放、断流、过期消息、用户接管和焦点异常的处理。健康异常的保护不被记为任务成功。
7. 完成短操作与录制/回放检查后，再开放 Finder/Preview 中的测试任务和长程采集。

测试时保持接电、图形会话已登录且可捕获。根据实验运行器管理保持唤醒；停止实验后恢复日常锁屏/电源行为。不要在此阶段自动禁用设备密码或改变全局安全设置。

## 网络与复现

桥接仅暴露本项目需要的接口，使用已授权的受限 SSH 转发或认证加密通道。连接信息放在忽略的本地配置/环境变量中，不写入 GitHub。不同主机的单调时钟须映射或报告延迟不确定度，不能直接相减。

固定屏幕布局、分辨率、光标、输入设备增益、滚动方向和系统版本。使用可重建的测试文件副本来重置任务。记录应用可见状态和任务重置版本，避免依赖个人桌面偶然状态。

每次接入和每次系统/应用升级后，重复必要的短链路验收并新增记录；不能沿用旧版本结果而不声明环境变化。普通鼠标/滚动桥接和 Apple 原生多点触控能力分别报告。

## 当前边界

M5 作为当前测试端，原生受限应用的实现与实测状态见 STATUS.md。M1 机型由用户确认，但尚未接入；以上 M1 配置是后续计划。未来真实手操作实体触控板时，再布置相应硬件位置和摄像头。
