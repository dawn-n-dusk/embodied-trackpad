# LEAP v1 力反馈视觉控制：源码通过，实际回合未通过

实验于 2026-10-31 UTC 完成，香港时间已到 11 月 1 日。当前结论：接触力反馈已接到真实仿真子步，指令因果链得到核验；这组控制参数仍无法安全推动光标靠近目标，不能进入训练数据采集。

## 实现与验收

Kimi 实现独立的纯数学法向导纳修正，再接入 `force-admittance` 模式。每张截图产生名义切向关节目标；每个 2 ms 子步消费前一步的真实接触记录，按食指接触点的 Jacobian 加入法向修正。图片、名义目标、修正意图、实际执行控制、物理触点及 GUI 回执分别记录。实际送入执行器的控制来自逐步记录，不能仅凭意图日志判断。

法向目标 0.8 N；增益 0.004 m/(N·s)；速度上限 0.002 m/s；每子步关节增量上限 0.0002 rad；每视觉周期总变化包络 0.005 rad。参数未经硬件标定。接触力属于教师特权反馈，不是 FSR 读数或学习策略输入。

独立运行 107 项纯数学、静态及 mock 检查全部通过。原先 `0.605 - 0.6` 的浮点舍入错误已修复：输入验证容差为 1e-12 rad，1e-9 rad 的实质超限仍拒绝，边界耗尽时仍不能继续向外运动。此前两个超时和一个主动终止分别保留；恢复记录的原始源码行数 202 更正为实测 189，原 SHA 和失败结论不变。[源码及恢复记录](../../experiments/records/v1-force-servo-source-20261031.json)。

## 这次失败缩小了哪些疑点

不是修正指令漏发，也不是共同包络把修正缩放为零。每周期名义切向动作让 MCP 增加约 0.00149 rad，当前法向修正抵消后仍留下正增量；实际 MCP 与其他屈曲关节的运动比例又不同于名义目标。结果是理想 Jacobian 的法向补偿没有转化成稳定接触。

101 次速度饱和提示需要检查法向控制余量，但不能凭此宣布增大增益就能成功。下一步只用已保存轨迹和两处静态重建，分析执行器、约束和名义切向目标的耦合，再决定是否采用更慢、分子步施加且让法向反馈优先的切向指令。P1、模型、1 mm 限值和 3 px 成功标准保持不变。

这仍是受限 GUI 中的教师控制诊断；没有合格 D1 数据、策略优化器、策略检查点或正在运行的项目直播。

## 诊断报告的独立审查修正

已保存的诊断报告存在记账和计算问题：把仅法向修正的变化量称作总指令变化，遗漏周期首个物理步，并错写最后一周期的分母。源码调用链还显示 32 次显式静态求解，模型准备额外 1 次，超过 26 次的合同上限；原报告称 22 次。原始文件保留，修正另记。完整的实际回合证据与 136 次指令核验不受此影响。两处静态结果支持检查切向指令对接触的影响，但其 warmstart 控制未记录，不据此声称完整因果隔离。下一步仅实现并检查分子步、力优先的数学合成模块。[审查与发布记录](../../experiments/records/v1-force-diagnosis-review-20261031.json)。

## 与 P1 固定轨迹的方向差异

P1 已验收的滑动主要是 `if_rot` 从 0 到 0.12 rad 的侧摆，三个屈曲目标保持 0.6/0.3/0.3 rad。当前 seed 2 的目标在屏幕水平正方向，需要屈曲关节协同。这一区别说明 P1 通过不覆盖任意二维轨迹，也不能把更换目标方向后的成功追记给 seed 2。后续按目标方向分别报告表现。
