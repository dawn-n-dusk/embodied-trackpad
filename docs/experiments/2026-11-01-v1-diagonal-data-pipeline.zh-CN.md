# 对角线数据管线：身份与时钟审核

2026-11-01。本轮先完善训练前的数据合同。具体实现由 Kimi K2.8 CLI 完成，协调者审查源码、独立运行离线检查并集成发布。没有新增仿真回合、数据索引或优化器训练，学习策略对角线成绩仍为 2/8。

## 已验收模块

`audit_episode` 与 `build_dataset_manifest` 可显式接收任务 profile 和采集批次。新对角线样本保留数值类别 0–7，并增加跨批次唯一的回合标识及任务类别标识；训练 0–3、验证 4/6、测试 5/7。冲突身份、错误划分、错误类别及未通过审核的回合引用会被拒绝。清单允许如实记录失败与缺失，不要求全部成功后才生成报告。旧默认输出在独立样例比较中保持完全一致。

独立运行了 60 项分组/导出/原审核器测试；另以旧源码比较样本与清单，完成 9 项兼容性和身份检查。最初 58 通过、2 失败，原因是新增测试缺少父目录，修复后 60 项通过；没有放宽业务断言。

纯函数 `validate_capture_timing` 已通过 22 项测试和 14 项独立检查。对之前保存的 45 帧（包括最终画面）重新校验，最大帧龄加时钟不确定性仍为 42.8535 ms，低于固定的 250 ms 上限。另验证了过期画面、时钟不确定性、阶段顺序、非法数值、缺失校准与后端版本冲突等拒绝路径。原始文件校验值保持不变。

时钟偏移的符号来自既有 `ClockReconciler`：应用时间 = Python 单调时钟 + offset，帧龄在特征提取结束 t3 处计算。四阶段耗时重新从时间戳计算，实际版本字段与 summary、metadata 绑定。旧数据缺失信息继续保留 null。标准库后端记录 Python 版本；不能错误地要求版本必须为空。

这两个模块的已验收源码为 `c393194`。前面两次源代码/测试调用及一次时钟模块调用超时，均保留文件、原始回执与用量，再缩小任务完成修复；超时或保存文件本身没有被视为验收。五次 Kimi 调用合计 777.7 秒，82 项独立测试合计约 3.58 秒；这些范围不同，不能将测试时间当成开发耗时。记录的 API 用量不等于会员额度或账单。[结构化记录](../../experiments/records/v1-profile-and-clock-helper-accepted-20261101.json)。
