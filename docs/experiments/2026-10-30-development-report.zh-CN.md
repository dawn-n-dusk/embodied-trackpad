## 已交付内容

Kimi 在两个独立工作树中实现协议/记录基础与 H800 环境探针；协调者制定接口和验收边界、独立复查、整理文档并发布。没有改动既有真实机器人服务。首轮公开内容包括架构、数据与 M1 测试台方案、开源许可、实验记录以及可运行代码。

协议基础实现六个首批消息契约、JSON Schema、运行时校验、分流记录器、确定性 mock CLI 和 Python 3.10–3.13 CI 配置。完整架构中的其它运行组件尚未实现。最终本地测试 **89 项通过**，独立边界复查 **9/9**，CLI 非法输入检查 **12/12**；同种子、固定时间戳的两次运行输出逐字节相同。

[H800 记录](2026-10-30-h800-probe.md)对应实际单卡作业：1/32 个世界、极小单自由度接触模型、12/12 检查通过。作业已经结束并释放资源。结果不证明 GPU 快于 CPU，也不证明完整手或训练环境已经就绪。

所有当前 CLI 输出都是 `mock_software_fixture` 且 `training_eligible=false`。没有动力学教师数据、真实 Mac 操作、训练策略或长程任务成功结果。

## 初版问题与返修

初版的 54 项测试虽然通过，协调者另行复现了同宽执行器换序、过期动作块、目录越界、mock 数据可被标为训练数据、缺失观察/成功证据引用，以及仅按字段名黑名单过滤 actor 数据的问题。写入刷新与异常中断状态也纳入返修要求。[ADR 0002](../decisions/0002-protocol-and-evidence-integrity.md)固定了对应的接口规则。

Kimi 在同一明确会话内更新了代码和测试，但返修调用达到 **1,200 秒**上限而超时，没有返回成功的最终验收报告。协调者检查已保存改动并执行测试，接着完成过时的文档、结果计数和校验和；生产代码未由协调者改写。初版结果、缺陷、超时与最终本地验收均保留在[结果记录](../../experiments/records/m0-foundation.json)中。

独立复查脚本曾把正确的 `unsafe_path` 拒绝码误判为失败；补充检查起初又缺少有效来源字段。修正这两处验证脚本问题后，构造器与记录器均拒绝越界路径且没有创建目录。旧复查记录保留于私有审计材料，不能将脚本错误说成产品仍有漏洞，也不能删掉错误检查的历史。

GPU 初次作业因 Warp 设备选择 API 调用不匹配而失败；修正后再提交成功。这个失败与耗时同样保留。GitHub CI 的实际运行结果单独追加记录，不能用本地测试代替。

## 下一验收边界与用户准备

下一里程碑是完整可动手/机械臂的 CPU MuJoCo 参考：固定模型来源与版本、关节/执行器映射、控制范围、安装姿态和碰撞，实际验证两指落板、指距变化与抬指重定位。随后接入响应触点的动态 GUI，先试采 **200–500 条真实动力学轨迹**。没有这条闭环时不启动正式 BC 训练。

M1 Mac 用于目标应用、屏幕和桥接，模型与训练运行在服务器。先准备专用本地账户、测试文件、固定分辨率/光标、稳定网络和约 50–100 GB 初始空闲空间；正式采集前选择支持的稳定 macOS 版本并固定。屏幕录制/辅助功能权限等到部署桥接时由用户在系统界面授予。

不用现在录个人日常工作视频。真实界面示范先采 100–200 条短流程，供上层理解；等仿真手与 Mac 桥接完成，再采带机器人动作的同步轨迹，供运动适配。长程数据先从 30–50 条 3–10 分钟任务起步，并独立留出 10–20 分钟评估任务。具体来源、时间对齐、失败数据与划分规则见[数据方案](../data-plan.zh-CN.md)。
