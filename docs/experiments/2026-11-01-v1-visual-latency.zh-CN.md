# 视觉链路的离线解码测量

低目标力教师的四个方向诊断中，一例因截图年龄超过 250 ms 而停止。以下测量使用已经保存的六张 800×600 PNG，没有新采集、仿真或优化器运行。

每张图预热一次、计时五次。当前解码器共调用 36 次，其中 30 次计时；解码中位数 78.979 ms、p95 251.340 ms、最大 350.226 ms。像素提取中位数 2.943 ms、最大 2.980 ms。协调者根据原始计时独立重算汇总，核对六张图片散列和尺寸未变。

该环境没有安装 Pillow，候选分支没有执行，也没有任何候选像素一致性结论。代码审查发现未执行分支误把已解码数组传入 BytesIO，下一任务必须在新文件中纠正，旧报告保留。Kimi 调度耗时 154.2 s，实际执行和缓存 token 记录见[结构化回执](../../experiments/records/v1-visual-decode-benchmark-accepted-20261101.json)。Token 记录不是会员计费金额。

这些数据说明现有解码器可能消耗较多帧龄预算；当时的失败回合没有记录分段计时，因此不能直接归因。250 ms 合格线继续保持，失败仍计入分母。

下一步在本项目既有虚拟环境中仅添加 Pillow 12.0.0 的二进制包，保留安装报告和包清单，再对相同六张图测量原解码器与候选的逐像素一致性和耗时。安装失败即停止，不改变其他包；候选测量成功也不直接修改生产链路或启动新回合。

## Pillow 候选：六张图的像素一致性通过

Kimi 在本项目环境中仅新增 Pillow 12.0.0；安装前后包清单核对表明原有包未改动，环境增长约 17.1 MiB。旧测量脚本与报告保持原样。

| 阶段 | 中位数 | p95 | 最大值 |
|---|---:|---:|---:|
| 同批原解码器 | 79.656 ms | 90.111 ms | 184.040 ms |
| Pillow 解码及数组转换 | 2.032 ms | 2.758 ms | 3.155 ms |
| 原图像的特征提取 | 2.827 ms | 3.732 ms | 4.787 ms |
| Pillow 图像的特征提取 | 2.833 ms | 3.213 ms | 3.350 ms |

每阶段 30 次计时，预热另计。独立审核重算全部统计，重新解码六张图片，逐像素、形状、类型和特征提取结果全部一致，输入散列未变。候选本次中位解码约快 39 倍，但不包含即将接入的完整严格校验、实时采集和控制开销。

测量按每次原解码器后接 Pillow 的固定顺序进行，没有完全抵消顺序偏差。报告中“数组在计时外”的字段不够准确：源码确认 NumPy 转换在解码计时内，比较和散列在计时外。此处以实际代码为准。Kimi 调度耗时 167.4 s。[独立记录](../../experiments/records/v1-pillow-benchmark-accepted-20261101.json)。

已派发源码任务：保持 stdlib 默认，增加显式 Pillow 后端，复用尺寸、CRC、解压上限、EOF 和滤波类型检查，并测试异常输入。当前尚未接入实时控制，不能把离线提速称为闭环成功。

源码任务在 240.1 s 上限停止，保留了三个文件的差异，但测试只添加了尚未使用的后端列表，没有完成测试报告。本轮将剩余工作缩小为测试参数化和依赖元数据，180 s 上限；不会仅凭源码已保存就验收。[超时检查点](../../experiments/records/v1-pillow-source-checkpoint-20261101.json)。

## 可选解码后端源码通过独立验收

缩小后的 Kimi 任务完成于 160.0 s。协调者独立运行 59 项测试全部通过，耗时 0.11 s、无跳过；再用生产函数分别解码六张已保存截图，像素、形状、类型和提取结果全部一致，输入散列未变。源码固定为 `2ac4bc2506767abab6913a537bace18b991964a5`。测试覆盖两后端的五类行滤波、RGB/RGBA，以及 CRC、截断、解压尺寸、EOF、尾随压缩数据、不支持格式和缺失依赖。默认仍为 stdlib，Pillow 必须显式选择。

Kimi 私有报告的 created_utc 使用了午夜占位值，未将其当作真实执行时间；独立审核使用实际 UTC。前次超时记录保留。该验收不涉及应用、物理或控制运行；下一任务仅接入教师探测器的后端选项和采集分段计时，仍需独立审核后才运行一个新回合。[源码验收](../../experiments/records/v1-pillow-source-accepted-20261101.json)。

完整接入任务在 240.1 s 内停留于规划，未保存修改或测试报告；缺失用量保持 unknown。已保留私有日志并拆成仅修改采集/日志两个函数的 120 s 任务，后端选择另行接入，不重复原来的宽任务。

拆分的采集计时任务在 120.1 s 处超时，但已保存两个函数的修改。协调者审查后独立运行 106 项测试（0.47 s）及人工时钟检查：采集、解码、提取耗时能分别复算，帧龄使用记录的 t3 和时钟偏移；300 ms 旧帧被拒绝且不产生动作。源码固定为 `91d8703272ca014808417b2c552c74fe0adec2a6`。这次验收依据实际代码和独立测试，未把超时当作 Kimi 完成；后端选择仍需另一项小任务。[计时验收](../../experiments/records/v1-capture-timing-accepted-20261101.json)。
