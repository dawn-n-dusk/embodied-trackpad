**Kimi 实施任务书：视觉反馈下的机器人触控板长程操作**

> 历史任务书。当前实施依据为同目录《docs/implementation-plan.zh-CN.md》与《docs/architecture.zh-CN.md》；下列固定指距二指主线、强制五指第二版及统一 BC→PPO 方案已被更新，不应继续据此启动实现。

2026-10-30。本文是后续实现的明确合同，本轮尚未执行这些实现包。已完成的两轮只读审计见 evidence。用户已明确允许使用既有 SuperPOD 账号和 H800；当前范围内不重复请求这项许可。实际系统缺少 macOS 权限时，由用户在系统界面完成授权。

**统一目标与禁止捷径**

给定一次任务指令，机器人自主控制手臂/手指与虚拟触控板交互，根据屏幕反馈调整，完成多个有依赖的步骤。策略只获得规定的图像、自身状态及明确模拟的真实传感器；动作最终落实为机器人关节/末端控制。Mac 的每个输入都必须来自实际仿真触点。

最新交付范围：至少二指与完整五指两个正式版本，以二指为主。先完成简单二指机构的完整训练、Mac 闭环及长程评估，再训练和验收五指版。二指应独立建模为可由简单硬件实现的机构；五指版正常开放全部手指和相应可控自由度。两版共享任务、视觉反馈、触点协议和桥接，各自适配低层动作。禁止把“拇指/食指不可用”列为主训练课程、主要研究目标或交付门槛；这种测试只在整体训练和主要评估跑通后作为附加项。

后端实现依据补充为 `后端训练架构与数据设计_v1.md`：MuJoCo 为训练与交互主后端，Isaac 用于独立高质量复核；二指先采用 XY+独立 Z1/Z2 四通道，完整五指采用 Shadow Hand，保持其关节/执行器耦合；低层 BC→DAgger→recurrent PPO，上层 Qwen2.5-VL-7B 基线与 LoRA SFT。参数均为待实验起点。

不允许：直接调用系统坐标点击代替机器人、利用 DOM/辅助功能树/应用状态替代视觉、重放预先成功的完整轨迹作为自主结果、子目标间偷偷重置、后台粘贴文本、把碰撞盒进入某位置直接判定应用任务成功。教师和独立评分器可访问真值，但不能泄露到测试策略。

实现使用独立原型目录和干净开发基线。现有 Embodied Intellegence 根仓库没有首个提交，禁止为了满足 runner 把整个历史目录提交。新服务使用独立端口和自己的进程身份，不接入已有 NexArm/D455/串口服务。遵循实际工作目录下的 AGENTS.md。

协调者制定目标/验收并独立看实际运行结果；Kimi 负责实现和测试。默认一位 Kimi 工人、一次一个有依赖的包。同一任务修正使用明确 session，不使用 --continue。新原型工作目录是否支持原会话需先核查，不假定可以跨目录直接续接。

**包 0：H800 训练环境验收**

- 目标：在 Slurm 实际分配的单 H800 上验证所选训练栈，输出环境锁定依据。
- 资源起点：normal 队列、SLURM_ACCOUNT 项目、1 GPU、约 10 分钟的验收任务；按本次实测策略不手工覆写系统内存默认分配。不是先申请 96 GPU。
- 允许文件：新原型 `hpc/smoke.sbatch`、`hpc/check_runtime.py`、环境清单与独立作业输出目录。
- 检查：记录 job ID、节点、GPU 型号/显存、驱动、运行时版本；小矩阵前后同步校验；仅在匹配依赖已准备好时检查 MuJoCo/MJX 最小环境吞吐。没有环境则明确记录，不以模块名或 CUDA toolkit 存在代替 PyTorch CUDA 验收。
- 约束：所有 GPU 计算在获分配的计算节点；不读密钥、不改变全局模块/权限、不停止他人任务、不加载无关大模型。环境安装只发生在明确的独立环境；首次执行合同需列出具体依赖和存储预算。
- 验收：退出状态与数值校验一致；明确哪些后端实际运行、哪些仅发现；不把 H800 当 RTX 渲染卡；保存可复现配置。

**包 1：手指—触控板物理接口**

- 目标：优先在独立小场景中建立简单二指机构，形成稳定、有身份的触点轨迹；协议预留完整五指版，单指动作仅作为二指版的基础测试。
- 允许文件：`sim/scene.*`、`sim/robot_asset.*`、`sim/assets/two_finger/*`、`sim/assets/five_finger/*`、`sensor/trackpad.*`、`protocol/*`、相关窄范围验收用例与 evidence。
- 二指结构：建议共享平面运动、两指独立落下/抬起并具顺应性，初期允许固定指距；若扩展捏合等手势，明确新增的指间自由度。普通平行夹爪能否切换单/双指接触须按真实机构检查。不能只把五指模型锁住三指就当作简单二指硬件已实现。
- 实现依据：主环境使用 MuJoCo 接触/执行器接口；参考已有 Isaac 的记录、控制与视觉验证模式，在独立场景复核，不能直接假定 PhysX 与 MuJoCo 接触结果相同。现有 home_search 和真实控制服务不改动。五指以 Shadow Hand 五指模型为准，不用四指 Allegro/LEAP 代替。
- 物理契约：关节限制/驱动明确；实际接触由动力学得到；一根指尖多个接触点合成一个触点；抬指结束该 identity；再次落指开始新 identity。原始接触与传感器判定分别记录。
- 触点协议至少含 sequence、physics_step、simulation_time、touch_id、phase、pad_x_mm、pad_y_mm、sensor_state；力字段明确单位/采样来源，不能把 impulse 当 force。
- 验收：无接触轨迹不能产生输入；边缘进出、抬指重定位、双指切换、迟滞与噪声测试；逐帧检查真实渲染与触点日志对应。脚本动作仅用于基础验证，不算自主完成。

**包 2：真实 Mac 在环桥接**

- 目标：传输屏幕图像，并把经传感器产生的输入送到真实测试应用。
- 允许文件：`bridge/mac/*`、`bridge/transport/*`、本地测试应用和对应验收记录。
- 第一阶段为 dry-run/事件记录；应用事件路径、限制范围和释放逻辑可审查后再运行实际输入。已有用户授权范围内可推进，不重复索要同一项许可；系统权限缺失则报告具体缺项，由用户授权，不改 TCC 数据库。
- 接口：桥接不暴露任意 click(x,y) 给策略。相对滑动经增益模型在桥接内部积分成光标位置；新触点不会导致跳转；按钮 down/up/drag 顺序完整。滚动属于明确声明的合成语义，不宣称原生 Apple 多指协议。
- 视觉：ScreenCaptureKit 图像包含光标，记录尺寸、缩放与捕获时刻；Retina 像素、逻辑坐标、窗口裁剪、显示器原点分别标定。首版单显示器/固定测试窗口。
- 传输：复用已授权 SSH 的受限转发模式；端点只监听所需接口并做会话校验。独立服务、独立端口，不复用真实机器人命令入口。所有消息有序号，旧动作不重放，断流释放按钮；发生用户接管或测试焦点丢失时停止注入。
- 验收：真实 Mac 测试窗口的移动、点击、拖动、滚动都能回看事件来源和视觉效果；不靠注入函数返回值判定应用成功。记录动作到画面的实际延迟。协调者亲自检查 GUI 与短视频。

**包 3：自主视觉动作策略与 H800 训练**

- 目标：给视觉目标后，策略自主改变手指/手臂动作，使光标和界面达到目标；不是记录好的手指轨迹。
- 允许文件：`policy/*`、`training/*`、`datasets/schema.*`、明确的仿真任务文件和训练配置。
- 推荐结构：低层连续动作策略 + 稳定的跟踪控制器；高层提出视觉子目标。先训练二指版，让策略自主选择单/双指接触和动作；再适配完整五指版的动作维度并训练。两版均正常开放自身手指，不加入禁用特定手指的训练任务；不假定两种机构直接共用低层检查点。
- 数据：主要使用经过动力学执行的教师示范、DAgger 学生状态纠正及策略采样。公开 OS-Atlas desktop 数据只用于截图定位，上层使用经验证的决策/恢复样本；Mac 人类使用日志若无关节记录，不能伪造成机器人示范。教师/critic 真值与运行 actor 观测隔离。
- H800：先单卡、同机 MuJoCo CPU workers 与 GPU learner 测吞吐/显存，再按瓶颈扩到 4/8 卡或验收 Warp/MJX。BC/SFT 可异步读取跨机器数据；PPO 必须记录并匹配采样策略版本，完成一批新轨迹后更新，不能把旧轨迹直接混入 on-policy batch。RTX 负责部署和高质量复核。
- 验收：未见目标位置、光标初态、增益和接触噪声下有视觉纠偏；比较开环、视觉伺服与学习策略；记录真实失败。高层推理慢时，低层控制仍能稳定保持/释放接触。

**包 4：二指优先的长程任务与两版对比**

- 目标：一次任务指令，连续完成 30–100 次语义交互量级的有依赖任务，实际时长和动作数如实记录；无人工逐步提示、无子任务间重置。
- 允许文件：`tasks/*`、`evaluation/*`、任务记忆/恢复逻辑和不可变的评估证据。
- 首个任务：从本地图片集合找出满足视觉条件的 5 张，预览核对，通过菜单复制到已有目标文件夹，再检查完整性。先在可重置工作台训练，后到 Finder/Preview 测试。使用独立测试文件副本。
- 任务记忆：记录完成项、当前界面、下一目标、上次动作与视觉结果、失败计数；完成判定需证据。漏点、弹窗、窗口位移、指针偏移后允许重观察与修正，但不改最终任务要求。
- 训练/测试划分：任务布局、图片内容、增益分别有未见条件。先完成二指版主评估，再以共同任务和配对初始条件评估五指版；主评估中各版的手指正常可用。
- 两版对比：报告任务成功率、时间、恢复能力、训练资源和机构复杂度。完整五指版属于正式交付；其额外手势单独验收，不使二指版承担其硬件无法执行的多指要求。机械自由度与 Mac 原生手势支持分别列出。
- 评分：独立验证最终文件与任务状态，和策略输入隔离；报告任务成功率、时长、人工接管、误点击、恢复、接触异常。展示所有评估运行清单，不能只交成功视频。
- 后续扩展：两版整体训练与主要评估跑通后，才可附加“拇指/食指不可用”等测试，且不计入主交付完成门槛。人形平台迁移也另行适配，可先固定坐姿/下身；模型许可、安装几何、关节限制与碰撞重新验收。

**每个包的交接格式**

返回实际改动文件、依赖/版本、执行过的检查、原始证据位置、失败/未验证项、资源占用与停止方式。不要把 exit code 0、单元测试、渲染画面或一次成功轨迹当作完整验收。视觉/行为修正集中反馈到同一具体会话，避免让协调者重复实现工人的工作。

**完成判定**

包 0–2 优先建立二指版的环境与桥接；包 3、4 先完成二指闭环训练和连续长程评估，再复用共同设施完成正式五指版并作对比。附加的手指禁用实验不阻塞两版交付。全部数字在实测前都只是设计值。当前已完成的是资源审计和方案，不填造任何这些包的运行结果。
