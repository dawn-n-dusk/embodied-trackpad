# Dream Machines π0.5 实际微调报告：证据、限制与项目取舍

核验日期：2026-10-31。原文发表于 2026 年 9 月：[Empirical results fine-tuning π0.5 on a real manufacturing task](https://dream-machines.eu/blog/pi05-fine-tuning)。本文结合原文实验、附录及作者公开数据集元数据评审；没有复现其训练，也没有把其成绩归入本项目。原始网页及解析文本留在本地忽略目录，公开仓库保存评审及[来源、校验和与独立统计](../../experiments/records/vla-review-sources-20261031.json)。

## 结论与建议的变化

将 **π0.5 机器人预训练权重的全量微调＋异步 RTC** 提升为本项目主要 VLA 实验候选；保留小型 CNN/GRU 或 ACT 作为控制链路与数据效率基线。先做少量高质量示范、学生状态上的纠错和执行调度，再判断是否需要 RL。不要先重建一个随机初始化的 80M Flow Matching 网络，并假定它会比预训练模型更省数据。

这不是认定 π0.5 已优于 GR00T 或适用于 LEAP。作者任务是双臂夹爪搬运和插入，本项目是四指触控板操作，视觉分布、动作语义、接触和任务判据均有明显差异。最终选择依赖相同任务、数据划分与测量预算上的闭环实验。

## 作者到底做了什么

| 项目 | 报告及公开元数据 |
|---|---|
| 任务 | 左臂从纸箱取出执行器，交给右臂，按指定方向插入托盘；固定取放顺序 |
| 平台 | 双臂 TRLC-DK1；公开数据为 `bi_dk1_follower`，状态和动作均 14 维 |
| 视觉 | 两个腕部相机＋一个全局相机；640×480 MJPG 采集，中心裁剪至 224×224 |
| 采集频率 | 50 Hz |
| 初始数据 | 7,271 回合，约 21 小时；两位操作者，VR/Gello 两种接口，四张桌子＋一个灯箱 |
| 过滤 | 质量评分 1–5，保留 ≥3；裁掉开始/结束空闲段 |
| 单回合边界 | 从休息姿态开始并结束；主要评估不是连续处理整箱的长程实验 |
| 标准评估 | 灯箱中固定箱体中心位置，顶层 40 个位置各一次；部分配置重复至 80/120 次 |
| 截止 | 最多 45 秒；10 秒无进展或明显无法恢复可人工提前判失败，有主观成分 |
| 判据 | 正确物体、正确顺序、正确孔位、正确方向、完整插入；另记录五级阶段进展 |

已读回公开元数据：21h v2 数据为 3,782,725 帧，按 50 Hz 是约 21.015 小时；HQ 为 198 回合、174,308 帧，约 0.968 小时；HQ＋纠错为 512 个存储片段、304,002 帧，约 1.689 小时。512 个片段不等于 512 次独立真实 rollout；其中包含拆分后的人工干预片段。没有下载完整视频或评估 rollout。

## 核心结果：保留分母

| 对照 | 原始计数 | 可支持的判断 |
|---|---|---|
| 全量微调基线 | 91/120 = 75.83% | 该任务的基础比较点 |
| LoRA r64，EBS 256 | 18/40 = 45% | 此配置低于全量微调 |
| LoRA r64，EBS 64 | 13/40 = 32.5% | 降低 batch 没有挽回结果 |
| LoRA r256，EBS 64 | 21/40 = 52.5% | 增加适配器容量仍未追平；训练样本暴露只有基线的一半 |
| 4h 灯箱数据／4h 五场景 | 13/40／50/80 | 相同小时数下，多样场景有更好结果；作者给出 Fisher p=0.0034 |
| 21h＋1h 高质量继续微调 | 36/40 = 90% | 针对交接和插入的高质量慢动作有价值 |
| 仅 1h 高质量，从 π0.5 权重开始微调 | 11/40 = 27.5% | 一小时不是普遍足够的承诺 |
| 上述 1h 策略＋240 回合纠错采集 | 标准位置 35/40 = 87.5%；多位置 19/40 = 47.5% | 纠错有效，但泛化差距仍很大 |
| 同一 21h 权重，优化 RTC | 74/80 = 92.5% | 执行调度本身可以显著改变成功率 |
| 21h＋1h 权重，优化 RTC | 39/40 = 97.5% | 小样本、单任务、主要在固定评估条件下的最佳结果 |
| 仅 PaliGemma 初始化、无机器人预训练 | 0/40 | 此任务依赖机器人预训练；不是完全随机初始化对照 |

原文标题中的 76%、93%、98% 是取整值。独立用公开计数重算 Wilson 95% 区间：91/120 为 [67.45%, 82.61%]；74/80 为 [84.59%, 96.52%]；39/40 为 [87.12%, 99.56%]。该区间只反映二项 rollout 抽样假设，没有包含训练随机种子、硬件状态变化、重复调参和模型选择的不确定性。

尤其不能把“98%”解释为连续长程操作几乎必成：仅作说明，若 50 个必要步骤各自独立成功率均为 97.5%，全程成功概率约 28.2%。真实步骤相关、可恢复，不能直接套这个数；它说明短技能成绩需要另外的长程评估。

## 微调设置及不能照抄的地方

| 项目 | 作者配置 |
|---|---|
| 模型 | π0.5，约 3.35B 可训练参数的全量微调 |
| 主训练 | 50k 更新，EBS 256，最高学习率 5e-5，WSD，末 10k 步二次退火 |
| 长训练对照 | 一条 210k 步轨迹；约 30k 后成功率未呈持续增长 |
| HQ 继续训练 | 从 21h/50k checkpoint 再训 5k，学习率 2e-5，末 1k 退火 |
| 仅 HQ | 从预训练 π0.5 开始微调 10k；不是随机网络训练 |
| 观测 | 单一观测时刻 `n_obs_steps=1`，三视角；不含 15 分钟持久记忆机制 |
| 动作 | 50 步块，对应 50 Hz 下 1 秒；主对照为绝对关节目标 |
| Flow Matching | 10 个推理积分/去噪步骤，BF16，时间采样 Beta(1.5,1.0) |
| 归一化 | 状态和动作 QUANTILES；文字长度上限 200 |

50k×256 = 1,280 万个采样训练项；它不是 1,280 万条独立示范。数据划分、有效动作 mask、采样跨度和帧间相关性比“多少 step”更能决定可比性。原文的 30k 饱和结论不能转成 LEAP 项目的固定训练预算。

作者在留出的 5% 完整回合上记录动作块 L2 误差和 Flow Matching 验证损失。它们能帮助判断训练是否饱和，却不能可靠排序后期真实任务成绩；剔除两个早期 checkpoint 后，动作误差与成功率的解释力几乎消失。不能只挑验证 loss 最低的 checkpoint，也不能因为 loss 后期升高就认定策略必然变差。

原文还发现夹爪塑性变化曾造成评估混杂，随后重跑评估。对本项目，这对应指腹磨损、FSR 预压/漂移、触控板增益和安装位置：需要在模型比较前后检查机械状态，交错评估候选策略，避免把硬件变化归因于算法。

## LoRA：改变优先级，不作普遍否定

作者把 LoRA 放到 VLM 和动作专家的全部线性层，r64 约 151M、r256 约 605M 可训练参数。r64 EBS256 学习率 5e-4；EBS64 的两种 rank 用 2.5e-4，alpha 均为 32。r256 只训 100k×64 = 640 万项，其他主要对照为 1,280 万项；r256/EBS256 没测。新本体导致低秩适配不足是作者的解释，尚不是被独立隔离的因果结论。

在作者四张 H100、EBS64 的匹配实验中，全量约 0.95 step/s，r64 约 0.90，r256 约 0.65；LoRA 在此主要节省优化器显存，没有兑现更快训练。不能推广成所有硬件和实现的速度定律。

作者报告全量训练静态状态约 37 GB，未包含 batch 激活；LoRA r64 在 RTX5090、batch8、gradient checkpointing、未 compile 的五步测量中峰值约 17.9 GB。两种数字不是相同口径，37 GB 也不保证任意 48 GB 卡能以目标 batch 运行。我们可在单张 48 GB 卡上做小 microbatch 显存试验，必要时再使用多卡分片；有效 batch 由 microbatch×卡数×累积次数确定，384 GB 不是单卡统一显存。

本项目建议：数据合格后做一个预注册的全量微调参考，再用同一数据与预算比较 LoRA。权重、动作适配和机器人预训练先验完整保留；不要为了缩到 80M 就直接删掉 VLM。报告没有验证这个删减方案。

## 最值得先复用的是 RTC 的实验方法

作者模型一次推理约 140 ms，但机械命令以 50 Hz 执行。50 步动作块不是每 20 ms 重新运行一次完整 VLA，也不是必须等整块执行完才观察。

- `reinfer` 是旧队列剩多少动作时请求新块；不是推理次数，也不是固定执行步数。
- 50 Hz 下 140 ms 约等于 7 步。生成期间这些动作已经由旧块执行，新块前缀必须与它们一致。
- 原文基线 R30/B16：请求时剩 30 步，约 7 步推理后还剩 23 步；新块前 7 步被冻结，后续至第 16 步受旧块引导，其余部分可调整。
- R50/B20 接近尽快重新请求，但仍受推理时间限制；不是 50 Hz VLA 推理。RTC 的引导补全也不等同于 ACT 在输出端做简单加权平均。

同权重比较：同步执行 21/40；R25/B50 为 20/40；R50/B1 为 32/40；R50/B16 为 35/40；R50/B20 为 74/80；R50/B25 为 68/80。作者在 B25 下加 compile 得到 29/40，低于未 compile 的 68/80，但样本较少，不能据此宣称编译导致退化或慢推理更好。

对触控板应测试：重规划间隔、动作块长度、推理延迟分布、接触阶段衔接，以及新目标是否使旧块过期。按下、保持、滑动、释放不能无条件平均；必须避免新块把正在释放的动作又混回按压。不要直接抄 R50/B20，因为我们的动作频率、接触变化和图像帧龄不同。

原文附录的 `n_action_steps=50` 描述参考配置的整块执行默认值；正文主要实验已启用 RTC，不能把这行误读成它们始终开环执行 1 秒。

## 数据质量与纠错：比“只收成功视频”更具体

只保留质量 ≥3 的过滤恰好去掉了掉落后恢复的数据。作者随后发现交接一失败就常常整回合失败。对于触控板，误触后撤回、失去接触后重定位、滑过目标再回调，应作为带明确来源标签的恢复示范保留，不能仅因整段曾失败就丢弃。

240 次纠错 rollout 中，212 次包含人工干预；作者用这些回合的干预片段，加另 28 次成功回合的完整轨迹和原始 HQ 数据训练。1.7 小时是留下的训练数据时长，不是整个系统投入的全部人力或采集墙钟时间。这是 human-gated DAgger 风格迭代，不能记作无人值守 RL。

操作者和遥操作接口在原文中混杂：一人用 VR、另一人用 Gello。差距不能证明 VR 普遍优于 Gello，更不能证明单目 MediaPipe 自动达到可用示范质量。我们应以跟踪误差、接触质量、纠错可操作性和最终策略结果选择采集方式。

四小时多场景的收益提示要覆盖不同目标位置/大小、布局、显示缩放、光标增益、初始指位和适度延迟。任意视觉增强不能替代这些因果变化。原文增强无明显收益是在其主要评估分布内，不能推出 GUI 不需要视觉变化；屏幕裁剪/仿射增强还须同步变换目标标签和坐标。

## 本项目的实际下一步

1. 先把用户已选的 LEAP v1 Full 建成新的 16 通道基线；此前 v2 的成功不可沿用。
2. 验证新截图确实改变后续电机动作，再开始 D1。FSR 尚不存在时显式设传感器 mask，不能伪造力觉。
3. 用少量有效教师轨迹先跑小基线，形成数据与执行诊断；随后用同一任务集验证 π0.5 完整预训练微调的价值。
4. 预留独立布局/增益测试集，记录采样和人工时间；根据学生 rollout 的失败补纠错数据。
5. 同一 checkpoint 独立扫 RTC 设置，分开比较学习质量和执行调度；重要结果扩大样本量、报告阶段失败及随机种子。
6. 按用户确认的路线，保留 RL 为中后期补充：达到任务标准可不做；效果不足则针对剩余瓶颈比较 residual RL、优势条件策略等后训练。先排除标定、数据和时序问题，再用独立任务评估决定是否有实际收益。论文贡献应由对照结果支持，不能预先宣称“通宵自动进化”。

本文未验证作者完整训练代码、所有 checkpoint、评估视频或训练种子复现。原文明确表示评估 rollout 未随数据发布、相对动作重导出数据未上传，且多数参数逐项实验，没有完整交互因素设计。其“VLA 最强”等表述依赖文中指定榜单与时间，不作为我们当前全模型排名。
