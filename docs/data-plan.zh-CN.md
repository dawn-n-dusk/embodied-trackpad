# 数据方案

首批数据从可重置动态 GUI 中的实际仿真动作产生；真实 Mac 视频用于界面理解，仿真手操纵真实 Mac 的同步轨迹用于适配。不要把录像播放、鼠标日志或软件点击直接标注成机器人关节示范。

以下数字是首批采样预算，不是当前已有数据、最终所需规模或模型性能保证。根据错误类型、覆盖率和学习曲线扩充，不先购买或收集一个庞大而没有动作标签的视频集。

## 为什么当前示例不能算训练示范

这里限制的是 M0 的软件占位样例，不是仿真数据。M0 人为构造图像引用、动作数组和结果消息，用来检查维度、时间、记录与错误处理；这些数组没有驱动机器人，所谓图像引用也不是操作后的真实画面。因此样例无法告诉模型某个关节动作会怎样改变界面。

这种 fixture 可以调试数据加载、张量形状或训练程序能否执行，但保持 `training_eligible=false`，不计入有效机器人训练量，也不能据此报告操作能力。真正经过 MuJoCo 执行器、接触、设备模型并改变可交互 GUI 的轨迹，可以在质量核验后进入训练；有实际过程的失败轨迹同样可能有价值。

`evidence_class` 与 `training_eligible` 是来源和使用边界，不是自动证明。仅把字符串改成 `physics_simulation` 不会创造物理证据。每批还须保存实际执行的源码/模型、状态与控制、触点、图像、时间对应和结果记录，并明确其任务范围。

## 数据批次

| 批次 | 起始规模 | 采集方式 | 使用边界 |
|---|---|---|---|
| D0 协议样例 | 少量确定性 fixture | 软件构造观测与动作消息，验证记录/回放/校验 | `training_eligible=false`；没有动力学，不是机器人示范 |
| D1 动力学教师试采 | 200–500 条短轨迹 | 可重置 GUI + MuJoCo 手模型 + IK/跟踪教师，实际产生触点 | 验证时间对齐、动作与结果、接触质量及教师成功/失败标签 |
| D1 扩展 | 2,000–10,000 条短轨迹，按结果逐批增加 | 随机目标、光标初态、增益、布局、接触阈值与延迟 | 运动 BC 与闭环评估；不冒充真实 Mac 分布 |
| D2 Mac 界面经验 | 首先约 100–200 条短流程 | 在独立 Mac 测试账户操作 Finder/Preview 等，保留截图、指令与结果 | 人直接操作 Mac 的记录用于认知训练；没有机器人动作时不用于关节 BC |
| D3 Mac/机器人配对 | 首先约 100–200 条短轨迹 | 人遥操作仿真手，或已具备短操作能力的策略操纵真实 Mac | 同时保存机器人动作、真实画面、事件来源和失败纠正，用于适配/DAgger |
| D4 长程与记忆 | 先 30–50 条约 3–10 分钟任务，再增加更长任务 | 单次指令，多阶段依赖，无子任务重置；保存自有记忆和纠正 | 记忆/恢复训练；10–20 分钟独立评估任务单独留出 |

D2 与 D3 不是相互替代的数据集。D2 可以较早收集真实界面语义；D3 要等机器人—触点—Mac 桥接链路完成。初期无需用户连续录制自己的日常工作。先用干净测试任务把采集程序和记录质量跑通。

## 第一组任务

运动课程包括光标接近目标、单击、双击、拖动到区域、双指滚动、抬指重定位、边界附近控制、失败后重新定位。可变指距/缩放先在受控 GUI 验证，Mac 原生多指输入另行验收。

Mac 首批选择内置应用和已有测试目录，减少依赖：打开与预览图片、按视觉条件选择图片、通过菜单复制到既有文件夹、滚动查找对象、调整窗口或内容视图、核对最终集合。任务避免要求尚未实现的实体键盘输入；若使用屏幕键盘，需明确纳入任务和数据协议。

长程任务应有真正的信息依赖，例如先看到目标样例，数分钟后在其它窗口中选择匹配图片；或者处理一批文件后记住已确认集合，避免重复。当前画面相同而历史不同的配对任务有助于检查模型是否使用记忆。

## 来源与标注

- 公开 GUI 数据如 OS-Atlas desktop 只补定位与视觉经验，筛选 Mac/桌面相关子集；记录数据版本、来源与许可。先检查一小份数据，不将全量下载当作任务进展。
- 教师可读仿真真值规划轨迹，但关节参考必须经过执行器与动力学，触点必须真正改变 GUI。保存规划参考和实际执行状态，不以“轨迹已生成”标为成功。
- 人类 GUI 日志可提供交互意图、步骤和光标轨迹目标。转成机器人动作时需要重新求解、实际执行与结果检查。
- 记忆监督只使用采样时刻以前的信息。尝试、观察成功和不确定分开；后验评分不直接泄漏进 actor 的当前观测。
- 保存教师失败、学生失败、人工纠正与自主成功的来源标签。奖励/评估器真值位于分离接口。

## 每条轨迹必须保留

`episode_id`、任务/布局/文件集 ID、时间戳与时钟域、图像/观察 ID、原始图像引用、执行器/关节顺序、实际状态、请求动作和最终执行动作、控制周期、目标/记忆版本、模型/控制器/桥接版本、增益与校准、随机种子、纠正来源、结束原因、结果证据和有效 mask。

屏幕统一采集，但保存策略实际消费的帧与时间映射；相同帧可按内容哈希去重，不能丢掉重复使用的时间关系。无损原始观察与有损回看视频分开。采集端先运行 5–10 分钟测实际压缩后吞吐，再制定磁盘限额；不要假定屏幕视频很小。原始 1920×1080 RGB 在 30 Hz 下约 187 MB/s，未经压缩接近 672 GB/小时。

高频状态与索引采用 Parquet/张量块或可无损转换的原始记录，图像以独立哈希引用保存。D0 的轻量 JSONL 记录不是大规模数据格式性能验收。

## 划分与质量门槛

按整段轨迹、任务、布局和测试文件集合划分训练/验证/测试，避免相邻视频帧进入不同集合。可从约 80/10/10 的分组比例开始，但最终独立任务集优先于凑比例。每类技能覆盖不同位置、速度、时延、增益和失败恢复。

先验收时间单调性、跨域时钟处理、图像—动作对应、动作维度/单位、终止边界、有效 mask、可回放性和角色隔离。随机抽查轨迹，核对输入事件确有动力学/触点来源。未过数据质量门槛的数据不进入正式训练。成功率只在定义清楚的独立测试集上报告。

## 发布与存储

GitHub 保存代码、配置、schema、数据说明、许可/来源、清单、校验和及小型可公开 fixture。大规模图像、视频、检查点保存在独立的实验存储；将来发布数据时另选合适的数据托管服务。

独立 Mac 使用干净测试账户与可公开测试文件，不录个人邮件、聊天、密码管理器或私人云盘。对真实截图逐批审查后再决定是否可公开；授权公开本项目不等于自动授权公开屏幕上的第三方或个人内容。

当前还没有 D1–D4 数据。每批实际采集后新增 datasheet 和实验台账，记录来源、规模、覆盖、质量问题、许可、保留位置与校验和。
